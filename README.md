# Day 4 – Doing Scrum – Sprint Simulation

This repository contains my answers for the Day 4 sprint-simulation assignment. Each question is in its own folder with my written answer and any supporting data or charts.

The assignment has three sets, with six questions in each set.

## What I'm working on

- Planning a sprint from velocity and capacity, and writing a measurable Sprint Goal.
- Breaking stories into tasks and running stand-ups.
- Handling impediments, blocked dependencies and mid-sprint scope changes.
- Drawing a burndown chart and calculating velocity.
- Preparing a Sprint Review and running retrospectives.
- Linking the Definition of Done to automation and a build pipeline.

## Assignment sets

### Set 1 – Digital Wallet Application – Mid-Sprint Change
Velocity and Sprint Goal, task breakdown, day-3 stand-up and impediment log, the refund-to-wallet change, the burndown chart, and the retrospective with the DoD mapped to a pipeline.

[Open Set 1](./Set-1-Digital-Wallet-Mid-Sprint-Change/)

### Set 2 – Airline Web Check-in – Blocked Dependency
Capacity and commitment, Sprint Goal with the DoR check, the impediment log, refinement with a story split, the Sprint Review agenda and an asynchronous stand-up.

[Open Set 2](./Set-2-Airline-Web-Checkin-Blocked-Dependency/)

### Set 3 – E-Learning Platform – Scope Change Handling
Sprint plan for velocity 30, impact of the certificate request, a blocked-developer stand-up, velocity with partly done work, a Start-Stop-Continue retro and a note on automation and the DoD.

[Open Set 3](./Set-3-E-Learning-Scope-Change/)

## How the folders are organised

Each question has its own folder. Inside, you can find:

- `README.md` with the question and my answer (it opens automatically on GitHub).
- Any supporting files, such as CSV tables, charts or a JIRA import file.
- `flowchart.svg`, which shows the steps I followed.

Each set also has a `SET-NOTES.md` file with a summary and the list of deliverables.

## Running

There is nothing to run – open the Markdown files on GitHub to read them.

Some questions say "from a supplied backlog" or "from a supplied completed-points table". These were not in the assignment document, so I prepared sample versions (`product_backlog.md`, `completed_points.csv`) and based the answers on them.
